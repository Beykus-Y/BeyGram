# Stable changelog BeyGram

Каждый новый Stable-релиз должен иметь собственное **человекочитаемое** описание
в файле `docs/releases/vX.X.X.X.md`. Номер **обязан совпадать** с
`release-version.properties`, встроенной версией APK и тегом `vX.X.X.X`.

Описания пишутся по-русски, для пользователей, **только о реально готовых изменениях**.
Не переносить в релиз описание незавершённой работы из DEV и не выдумывать функции.
Можно использовать один или несколько заголовков из списка ниже.

Пример **шаблона**, а не список выпущенных функций:

```markdown
# BeyGram 0.0.0.7

## Что нового
- Добавлена новая функция, проверенная в Stable.

## Улучшения
- Ускорено открытие часто используемого экрана.

## Исправления
- Исправлена воспроизводимая ошибка при отправке сообщений.

## Известные проблемы
- Описано существующее ограничение и способ его обойти.
```

Разделы без изменений нужно убрать. Каждое изменение должно быть отдельным
элементом списка `- `. Не использовать `TODO`, `TBD` или заглушки.

**Внимание:** это демонстрационные формулировки, не готовый файл
`v0.0.0.7.md`. Заполнить его можно только после проверки конкретной версии.

## Публикация

1. Установить следующую версию в `release-version.properties` и подготовить
   соответствующий `docs/releases/vX.X.X.X.md` **в том же PR**.
2. Проверить: `python3 scripts/release_notes.py validate` и
   `python3 -m unittest discover -s scripts -p 'test_*.py'`.
3. После мержа в `main` CI собирает и подписывает APK. Публикация использует
   **только** успешно собранный APK того же коммита.
4. При публикации CI проверяет changelog, добавляет автоматически сформированный
   технический список PR и создаёт **Draft** релиза. После загрузки обоих
   файлов (APK + manifest) Draft становится публичным Stable Release.

Маркер `<!-- TECHNICAL_CHANGELOG -->` добавляется **только CI**:
он отделяет автоматически сформированные подробности для разработчиков
от пользовательских заметок, отображаемых на экране обновлений.

При ошибке публикации повторный запуск может продолжить существующий Draft
для того же коммита; **опубликованные** релизы не должны перезаписываться.
