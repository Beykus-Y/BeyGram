# Profile 2.0 C: единая адаптивная сцена (дизайн)

Issue: #1138. Статус: проектный документ для архитектурного ревью Sonnet. Реализация начинается только после ревью.
Основание: ручная проверка DEV 697 на Samsung M21 (раскрытие фото, сворачивание при прокрутке) и актуальный код DEV 9093fa00.

## 1. Что не так в текущей реализации (по коду)

Все ссылки на `app/src/main/java/com/beykus/beygram/ui/screens/profile/ProfileScreen.kt` и `ui/motion/ChatProfileTransition.kt`.

1. **Фото — второй элемент, а не состояние аватара.** `ProfileExpandedPhoto` вставлен в содержимое прокрутки между аватаром и именем (блок `if (sceneC && photoExpanded ...)` около строки 300). Круглый аватар остаётся на месте, поэтому на экране две копии фото (скриншот 1).
2. **Знаменатель сворачивания меняется при раскрытии.** `collapse = collapseFractionForScroll(scroll, identityHeightPx)`, а `identityHeightPx` измеряется по всему блоку шапки (`onSizeChanged`, строка ~272). Раскрытие увеличивает блок, и кривая сворачивания сдвигается.
3. **Оверлей не знает о фото.** `ProfileCollapsingOverlay` двигает только аватар (112 dp), имя и статус между позициями «в нуле» и компактными. Раскрытое фото остаётся обычным прокручиваемым контентом: его обрезает toolbar, оно не участвует в сворачивании (скриншот 2).
4. **Пустое место после сворачивания.** Высота фото и `Spacer(12 dp)` остаются в потоке при `collapse = 1`, поэтому между шапкой и музыкальной карточкой остаётся пустой блок (скриншот 3).
5. **Параллакс — отдельный эффект.** Он двигает картинку внутри отдельного блока и не связан с геометрией сцены.

Вывод: это две независимые системы (шапка со своими переходами и дополнительный блок фото). Дополнять их offset/alpha/Spacer нельзя, это и привело к текущей картине.

## 2. Целевая модель: одна сцена

### 2.1. Один объект для аватара

Аватар остаётся одним элементом, который уже рисует `ProfileCollapsingOverlay` (в окне, через `graphicsLayer`). Раскрытие **морфит этот элемент**:

- форма: круг (`CircleShape`) → скруглённый прямоугольник (радиус 24 dp);
- размер: 112 dp → ширина содержимого шапки, высота ограничена (см. 2.3);
- позиция: из центра шапки, по той же функции `lerpRect` от текущего прямоугольника к прямоугольнику раскрытия.

В установившемся состоянии на экране одна фотография. Отдельного `ProfileExpandedPhoto` в потоке прокрутки больше нет.

### 2.2. Состояния и параметры

Одна чистая модель (без Android, для тестов), назовём `ProfileSceneModel` (имя согласовать с существующими типами):

- входы: `scrollPx` (Int), `revealFraction` (0..1, анимируется по тапу, пружина), `viewportWidthPx`, `viewportHeightPx`, `insetsPx`, `hasPhoto`, `reduceMotion`;
- выход на каждый элемент: прямоугольник, радиус, альфа, сдвиг параллакса (отдельно для слоя с фото).

Состояния (все из одной модели):
- обычное: круг 112 dp в центре, имя и статус под ним;
- раскрытие (переход): `revealFraction` от 0 до 1, одновременно меняются форма, размер, позиция аватара, имя и статус сдвигаются вниз на высоту фото;
- раскрыто: `revealFraction = 1`, фото в центре шапки, имя и статус под ним;
- сворачивание при прокрутке: `collapse = scrollPx / travelPx`, где `collapse` влияет на аватар, имя, статус, фон и альфы;
- компактная шапка: `collapse = 1`, аватар в toolbar, ничего не выходит за его границы.

### 2.3. Геометрия

- **Знаменатель сворачивания фиксирован**: `travelPx = baseHeightPx + revealExtraPx`, где `baseHeightPx` — высота шапки без фото, а `revealExtraPx` — дополнительная высота раскрытого фото. Не измерять `identityHeightPx` по живому блоку с фото. Измерение делать по модели, а не по `onSizeChanged` содержимого.
- **Размер раскрытого фото** (адаптивный, не 260 dp): ширина `min(viewportWidth - 2 * 20 dp, 420 dp)`; высота `min(ширина, 0.42 * viewportHeight)` при landscape и малой высоте; радиус 24 dp. Квадрат допустим только если помещается.
- **Отступ контента** = `headerHeight(scroll, reveal)` из модели. Никаких независимых `Spacer` в шапке. При `collapse = 1` отступ равен компактной высоте, пустого блока нет.
- **Имя и статус** лерпятся от «в нуле» к компактным прямоугольникам, как сейчас, но их «в нуле» позиция берётся из модели, а не из `onGloballyPositioned` содержимого.

### 2.4. Параллакс

- Слой картинки внутри морфящейся формы, сдвиг `translationY = clamp(scroll * 0.2, 0, slack)`.
- `slack = height * (scale - 1) / 2` вычисляется из **фактического** размера формы, а не константой (уже есть `parallaxMaxPx` и тесты, переиспользовать).
- Reduced motion: сдвиг 0 (уже есть `rememberSystemReducedMotion`).
- Параллакс читается в draw-фазе (`graphicsLayer`), без рекомпозиции шапки.

### 2.5. Жесты и Back

- Тап по аватару в C: первый тап раскрывает (`revealFraction` → 1), второй открывает галерею (`showPhoto = true`). Уже реализовано, сохранить.
- Back: при `revealFraction > 0` сначала анимированно сворачивает фото (`revealFraction` → 0), потом выходит. Текущий `BackHandler(enabled = backClosesExpansion(...))` после обработчиков профиля сохранить.
- Predictive Back при `profileTransition != null` (строка ~183) работает как раньше. Перед стартом полёта `revealFraction` анимируется к 0, чтобы полёт начинался из компактной или обычной геометрии, которую знает контракт `ChatProfileTransition`.

### 2.6. Переходы чат ↔ профиль (контракт)

- `reportAvatar`, `reportTitle`, `reportStatus` сохраняют сигнатуры и смысл: прямоугольники в окне, в состоянии «в нуле» и с учётом сворачивания (`lerpRect`, `shrunkAroundCenter`).
- Во время раскрытия отчётный прямоугольник аватара — текущий морфящийся прямоугольник. Полёт стартует только при `revealFraction == 0` (см. 2.5), поэтому контракту не нужны новые поля.
- `ProfileCollapsedSwitch`, `expandedHeaderIdentityAlpha`, `compactToolbarIdentityAlpha` использовать как есть.

### 2.7. Фото и производительность

- Одна декодировка: морфящийся аватар показывает маленький файл, после загрузки большого файла переключается на него внутри того же узла (без второго `LocalMediaImage` в потоке). Большой файл запрашивается при раскрытии.
- Нет `observeFile` на каждый кадр: подписка на файл одна, на узел аватара.
- Значения, меняющиеся каждый кадр, читаются в `graphicsLayer`/draw-фазе; состояние шапки обновляется не чаще, чем меняется `revealFraction` или квантованный `collapse`.

### 2.8. Что не меняем

- Вариант A (`ProfileScreen` без C) — код не трогаем, ветка `ProfileVariant.A` остаётся как есть.
- Группы и каналы (`GroupProfile.kt`) — вне C.
- Музыкальная карточка, `PlaybackEngine`, мини-плеер — только позиция в потоке через модель; их не переписываем. Работает другой агент (Music Player V3, #1160).
- Галерея `ProfilePhotoGallery` — без изменений, открывается тем же флагом `showPhoto`.
- Флаг эксперимента `ProfileSceneSettings` (выключен по умолчанию, доступен в Stable через «Эксперименты») — без изменений.

## 4. Последовательность PR (каждый — отдельный PR в DEV, ревью Sonnet по актуальному head)

1. **P1 — модель без UI.** `ProfileSceneModel` (чистые функции: travel, размер раскрытого фото, прямоугольники, collapse, slack параллакса) и юнит-тесты. Экран не меняется.
2. **P2 — морф аватара для C.** Раскрытие меняет форму и позицию аватара в оверлее, блок фото из потока удаляется, отступ строится из модели. Только при флаге C.
3. **P3 — сворачивание раскрытого фото.** `collapse` с фиксированным `travelPx`, имя и статус из модели, компактная шапка без пустых блоков.
4. **P4 — параллакс на морфящемся слое.** Slack из фактического размера, reduced motion, без рекомпозиции.
5. **P5 — pull-down (растяжение).** Только после P1–P4 и ревью.
6. **C3 — многослойная сцена** (фон, глубина, плотность) и закреплённые подарки через общий рендерер Gifts 2.0 (#1135). Зависимость от #1152 уже в DEV (`0194d766`), но #1135 не блокирует P1–P4.

## 5. Тесты и проверки

- Юнит-тесты модели: travel не меняется при скролле; раскрытие не меняет знаменатель во время скролла; `collapse` в [0, 1]; компактное состояние не выходит за toolbar; slack параллакса зависит от размера формы; reduced motion → 0; Back при раскрытии не выходит из профиля.
- Инструментальных тестов на устройстве в облаке нет. Визуальная приёмка только на устройстве (Beykus). Не заявлять визуальную приёмку по тестам и зелёному CI.
- Чек-лист устройства (Samsung M21 и современное устройство): раскрыть, прокрутить, свернуть, вернуть скролл, назад (обычный и Predictive), полёт чат ↔ профиль, галерея повторным тапом, без фото, длинное имя, landscape, крупный шрифт, reduced motion, TalkBack.
