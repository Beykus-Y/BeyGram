Issue: #1138. Статус: дизайн после архитектурного ревью Sonnet (комментарий 7158385111 в PR #1172). Реализация не начинается до повторного ревью.
Основание: ручная проверка DEV 697 на Samsung M21 (раскрытие фото, сворачивание) и код DEV 9093fa00.

## 1. Проблемы текущей реализации (по коду)

Ссылки: `app/src/main/java/com/beykus/beygram/ui/screens/profile/ProfileScreen.kt`, `ui/motion/ChatProfileTransition.kt`.

1. **Фото — второй элемент, а не состояние аватара.** `ProfileExpandedPhoto` вставлен в поток прокрутки между аватаром и именем. Круглый аватар остаётся на месте, на экране две копии (скриншот 1).
2. **Знаменатель сворачивания меняется при раскрытии.** `collapse = collapseFractionForScroll(scroll, identityHeightPx)`; `identityHeightPx` — `onSizeChanged` по блоку шапки. Раскрытие увеличивает блок, кривая сворачивания сдвигается.
3. **Оверлей не знает о фото.** `ProfileCollapsingOverlay` двигает только аватар 112 dp, имя и статус. Фото остаётся в прокрутке, его обрезает toolbar (скриншот 2).
4. **Пустой промежуток после сворачивания — причина не доказана.** Гипотезы: (а) `identityHeightPx` не совпадает с высотой стейджа (внешние padding 12/16 dp, бейджи вне измеряемого блока); (б) высота не обновилась после раскрытия. Воспроизвести на устройстве до реализации: показать debug-подсказку с `identityHeightPx`, высотой стейджа и `scroll` (только в debug-сборке, не в PR) и снять кадры при `collapse = 1`.
5. **Перекомпоновка на каждый кадр.** `collapse.value` читается в композиции (условие оверлея, аргумент `collapse = ...`, условие клика), поэтому весь профиль перекомпоновывается при прокрутке. Для C этого не допускать. Для A не менять.

## 2. Целевая модель

### 2.1. Один рендерер сцены для C

- В потоке прокрутки для C остаётся **прозрачный стейдж**: его высота из модели, он держит клик и семантику аватара. Он ничего не рисует.
- **Весь видимый контент сцены рисует оверлей** (аватар, фото, имя, статус, бейджи). Оверлей рисуется **всегда** в C, а не только при `0 < collapse < 1`.
- Клип по нижней границе toolbar применяется **только к слою фото**. Так широкое фото не перекрывает кнопку назад и меню. Аватар, имя и статус не клипуются: их компактное положение уже внутри toolbar.
- Стейдж и оверлей получают одну и ту же модель через один источник; рассинхрона между потоком и оверлеем нет, потому что поток ничего не рисует.

### 2.2. Морф как маска, не масштаб

- Слой картинки имеет размер **раскрытого** состояния и масштабируется **равномерно** (cover): `s = max(clipW, clipH) / стороны слоя`. Пропорции сохраняются, картинка не искажается. Форма клипа (круг → скруглённый прямоугольник, радиус интерполируется) и размер клипа меняются в draw-фазе через `graphicsLayer` (`shape`/`clip`). Масштаб `s` и параметры клипа входят в выход модели и тестируются.
- Файлы: маленький и большой кроссфейдятся **внутри одного узла** (одна декодировка на переход, без второго `LocalMediaImage`).
- Скрытые поля: позиция и размер клипа интерполируются из модели; `lerpRect` использовать для прямоугольника, форма — отдельно.

### 2.3. Модель сцены

Чистая модель (без Android), входы:

- `scrollPx` (Int), `revealFraction` (0..1), `viewportWidthPx`, `viewportHeightPx`, `insetsPx` (включая cutout), `fontScale`;
- `stageTopPx` (окно, y стейджа при scroll 0), `toolbarBottomPx`, компактные прямоугольники аватара, имени и статуса из toolbar (`compactAvatar`, `compactTitle`, `compactStatus`);
- `hasPhoto`, `isOwnProfile` (состав блоков);
- **измеренные размеры текста и бейджей** из невидимого стейджа (`SubcomposeLayout` или отдельный measure-проход): высота заголовка (с переносами длинных имён), статуса, бейджей Premium/Verified;
- `reduceMotion`.

Выход: прямоугольники и формы для аватара, фото, имени, статуса, бейджей, фона, параллакса; отступ контента; `collapse`.

Состояния: обычное; раскрытие (переход `reveal` 0→1, только при `scroll == 0`); раскрыто; сворачивание при прокрутке; компактная шапка.

### 2.4. Геометрия и инварианты

- `travelPx = baseHeightPx + revealExtraPx`. `baseHeightPx` и `revealExtraPx` считаются моделью из измеренных входов, а не из `onSizeChanged` контента.
- Инвариант (тест): при `collapse = 1` нижний край видимой сцены (максимум нижних краёв аватара, имени и статуса) не ниже нижнего края toolbar и не выходит за него. `travelPx` не зависит от `reveal` (раскрытие не меняет знаменатель).
- Размер раскрытого фото: `min(ширина − 2·20 dp, 420 dp)`, высота `min(ширина, 0.42·высоты)`, с учётом insets/cutout. Нижняя граница: если высота раскрытого фото меньше аватара, раскрытие отключается (`hasPhoto`-подобный флаг модели).
- Без фото (инициалы): `reveal` недоступен, высота стейджа не зависит от `reveal`.

### 2.5. Раскрытие и сворачивание: правила

- **`reveal` меняется только при `scroll == 0`.** Знаменатель `travelPx` не должен прыгать во время прокрутки.
- Тап по аватару: при `scroll == 0` и `reveal == 0` — раскрыть; при `reveal == 1` — галерея (`showPhoto = true`).
- Любой выход из C при `reveal > 0` (стрелка, кнопка назад, жест Back): **сначала** анимированно сворачивает фото (`reveal` → 0 и `scroll` → 0), **потом** выход. Полёт чат ↔ профиль стартует только из круглого состояния. Единая точка: функция `leaveProfile()`, которую вызывают стрелка и `BackHandler`/`PredictiveBackHandler`.
- Прокрутка во время `reveal > 0`: сворачивание через `scroll` разрешено, но `reveal` не меняется, пока `scroll > 0`.

### 2.6. Отчёты геометрии для перехода чат ↔ профиль

- `reportAvatar`, `reportTitle`, `reportStatus` больше не строятся на `onGloballyPositioned`. Они публикуются **из модели** (`snapshotFlow` по производным значениям модели, без чтения в композиции) и по запросу при `beginPop` и `beginGesturePop`.
- Сигнатуры контракта не меняются (`ChatProfileHeaderTarget`, `collapseFractionForScroll` используются потоком A и полётом — не трогать).
- Инвариант (тест): отчётные прямоугольники равны прямоугольникам модели при тех же входах.

### 2.7. Параллакс

- Сдвиг слоя картинки внутри клипа: `clamp(scroll · 0.2, 0, slack) · reveal`.
- `slack = (высота слоя − высота клипа) / 2` от **высоты слоя** (слой имеет размер раскрытого состояния, см. 2.2), а не от текущей формы. Для этого `parallaxMaxPx` принимает высоту слоя.
- Reduced motion: сдвиг 0.
- Читается в draw-фазе, без рекомпозиции.
- Параллакс умножается на `reveal`: в свёрнутом состоянии слой стоит на месте.

### 2.8. Доступность

- Кнопка аватара (контент и `stateDescription` «раскрыто/свернуто») живёт в стейдже в потоке, потому что оверлей `clearAndSetSemantics`.
- При смене состояния озвучивать (`stateDescription`). Раскрытое фото при `collapse > 0` не кликабельно (клик отключён, как сейчас), фокус не должен оставаться на невидимом элементе.
- Reduced motion: раскрытие и сворачивание без пружины (мгновенно или короткий кроссфейд), параллакс 0.
- Predictive Back: первый этап — обычный `BackHandler(enabled = reveal > 0)`, превью жеста не показывается; записано как известное ограничение, позже перевести на `PredictiveBackHandler` с прогрессом сворачивания.

### 2.9. Состояние при повороте

- `photoExpanded` уже `rememberSaveable` (булево). Дробное `reveal` не сохраняется. После поворота `reveal` восстанавливается в целевое значение сразу, без анимации. `scroll` клампится к новой высоте.

### 2.10. Слоты и граница

- Витрина закреплённых подарков (C3): в модели зарезервирован слот высоты, рендер подарков в оверлей не добавлять (общий рендерер #1135 в нормальном потоке).
- Музыкальная карточка и мини-плеер: только положение от высоты стейджа; их код не трогать (Music Player V3, #1160).

### 2.11. Что не меняем

- Вариант A: `ProfileScreen` без ветки C — код не менять; diff по профилю A пустой в каждом PR.
- Группы и каналы (`GroupProfile.kt`) — вне C.
- Галерея `ProfilePhotoGallery`, флаг `ProfileSceneSettings` — без изменений.
- Сцену C вынести в отдельный файл/компонент; ветвление на входе, не внутри шапки A.

## 2.13. P2b: настоящая сцена (v2, после ревью fe9bb2fc)

Контекст: P2a (#1183) убрал второе фото и выбор «раскрыть» и не использует модель. P2b подключает модель (#1177, DEV `8cb642ad`; P1.1 — `34ccd5f7`, отдельные интервалы) к колонке идентичности **только в C**. Профиль A и выключенный эксперимент не меняются.

### 2.13.0. Что явно в P2b, а что в P3

- **P2b:** рукопожатие оверлея как в A. В покое (`collapse = 0`) имя, статус и аватар рисует поток, при сворачивании оверлей (`overlayReady`). Позиции потока совпадают с `avatarRect/titleRect/statusRect` модели при `collapse = 0` (тест). Единого рендерера ещё нет.
- **P3:** единый рендерер сцены: оверлей рисует всегда и является единственным рисующим узлом; морф-маска фото. Раскрытия в P2b нет (тап — галерея, как в A).

### 2.13.1. Стейдж: собственный Layout, без задержки

- В C колонка идентичности получает **собственный `Layout`** (стейдж). Он в одном проходе измеряет title, status и badges с явной шириной `contentWidth − 2·margin`, передаёт измерения в модель и размещает детей по rect модели. Никаких `onSizeChanged` → состояние → перекомпоновка: первого кадра с запасной раскладкой нет.
- Высота стейджа — из модели (`stageHeightPx`) и выставляется тем же проходом. Результат (высоты, stage top, rect) публикуется в холдер, который читают только draw-фаза и отчёты перехода.
- Длинное имя, fontScale и смена статуса меняют высоту в том же кадре, в котором пересчитывается модель.

### 2.13.2. Интервалы и нулевые элементы (P1.1)

- Интервалы раздельные: аватар → имя 16 dp, имя → статус 4 dp, статус → бейджи 0 dp (как в A).
- Интервал применяется только к элементу с высотой: нет статуса — нет интервала и нет пустоты; нет бейджей — нет интервала. Это закреплено в модели и тестах.

### 2.13.3. Знаменатель, `toolbarBottom` и `maxScroll`

- `travelPx = stageHeight + stageTop − toolbarBottom` (модель). `collapse = scroll / travel`; один источник, без `identityHeightPx`.
- `toolbarBottom` измеряется у самого `ProfileToolbar`, не из `stageTop`. `LinearProgressIndicator` в C выносится из потока скролла (рисуется поверх, как сейчас в A вне колонки); тогда появление индикатора не сдвигает `stageTop` и не дёргает `collapse`.
- Короткие профили: минимальная высота содержимого `heightIn(min = высота колонки + travelPx)`. Цена — ровно `travelPx` у коротких профилей и 0 у длинных. Высота колонки берётся из `BoxWithConstraints`, а не из состояния с задержкой. Продуктовое решение (пустое место у короткого профиля ради сворачивания, или оставить развёрнутым) — за Beykus на устройстве.

### 2.13.4. Отчёты перехода чат ↔ профиль

- Отчёты (`reportAvatar/Title/Status`) публикуются **только** из модели и только после готовности всех входов: stageTop, высоты, toolbarBottom, compact rect. Пока хоть один вход не измерен — отчётов нет (null-гейт), иначе полёт приземлится не туда.
- Переопубликовываются: при смене fingerprint (поворот), при завершении входного перехода (`AnimatedContent` завершён) и при смене compact rect.
- `stageTop` берётся из позиции стейджа в координатах корня после стабилизации (`onPlaced`/координаты `Layout`), а не из захвата посреди анимации предков. Проверка на устройстве: полёт чат → профиль и обратно без прокрутки.
- Фингерпринт окна и `ChatProfileTransitionController` не меняются.

### 2.13.5. Чтения `collapse` и рекомпозиция

- Условие оверлея («показывать оверлей») и кликабельность аватара («тап открывает галерею только при `collapse ≤ 0`») вычисляются как `derivedStateOf { Boolean }`: рекомпозиция только на границах 0 и 1, не на каждом кадре.
- Сами значения `collapse`, `avatarRect` и т. п. читаются только в `graphicsLayer`/draw-лямбдах.
- Ключи `remember`: только `sceneC`, плотность, размер окна, `info.id`. `hasPhoto`, `reduceMotion`, `info` — через `rememberUpdatedState` (чтобы не было устаревших захватов и пересоздания `derivedStateOf`/`LaunchedEffect`).

### 2.13.6. Гейт и A

- Все новые узлы, наблюдатели и ветки — только под `sceneC`: `if (sceneC) StageLayout(...) else <текущая раскладка A>`. Наблюдатели A не создаются.
- `collapseFractionForScroll(scroll, identityHeightPx)` и сигнатуры `ChatProfileHeaderTarget` не меняются.
- Проверка диффа: в PR P2b диф профиля A пустой, кроме общих точек входа (ветвление на входе).

### 2.13.7. Заголовок, статус, бейджи, крупный шрифт

- Заголовок и статус в стейдже сохраняют `maxLines` и стили из A; если в A не ограничены, не ограничиваем (записано).
- Крупный шрифт и ландшафт 360 dp: стейдж может быть выше экрана — допустимо (travel больше экрана), проверяется на устройстве; `heightIn(min)` из 2.13.3 корректен и в этом случае.

### 2.13.8. TalkBack

- Строки `a11y_profile_photo_expand` и `a11y_profile_photo_expanded_state` удаляются в P3.

### 2.13.10. Тесты и проверка

- Юнит (модель): паритет суммы детей, `travel = stage + top − toolbar`, монотонность, `maxScroll ≥ travel` (через `heightIn(min)`), нет статуса / нет бейджей (без пустоты), отчёты равны прямоугольникам модели, `collapse` при тех же высотах совпадает с A там, где интервалы совпадают.
- Не юнит: вид и переход — только на устройстве. Чек-лист в PR: короткий профиль; профиль без статуса и бейджей; поворот при `scroll > 0`; полёт чат → профиль и обратно без прокрутки; большой шрифт; TalkBack; выключенный эксперимент.
- Визуальная проверка в облаке не проводится; в PR это пишется явно.

## 2.14. P3: раскрытие фото одним визуальным аватаром (v2, после ревью 0a8f7ef2)

Контекст: P2b (#1187) даёт сцену C: стейдж, модель, сворачивание, отчёты перехода после измерений. Раскрытия нет. P3 добавляет раскрытие аватара в одну непрерывную фотографию. Профиль A и выключенный эксперимент не меняются. Блокеры ревью 0a8f7ef2 (B1–B5 и дыры 1–10) закрыты ниже.

### 2.14.0. Требование результата

- Один видимый аватар: на экране одна поверхность фото/аватара, которую трансформирует модель. Фото не открывается вторым элементом.
- Непрерывный морф: круг 112 dp → фото (`photoWidthPx × photoHeightPx`) по `revealFraction`, в одном узле.
- Геометрия имени, статуса, бейджей и тулбара — из той же модели. Раскрытого состояния с отдельной геометрией нет.

### 2.14.1. Разбиение на P3a и P3b

- **P3a:** слой аватара/фото в C рисуется всегда; при `reveal = 0` он совпадает с P2b (паритет rect); полёт чат ↔ профиль идёт от слоя. Раскрытия нет: тап открывает галерею, как в A. Принимается на устройстве.
- **P3b:** раскрытие, конечный автомат, Back и стрелка, `PredictiveBackHandler`, reduced motion, TalkBack-состояния, очистка строк и удаление `ProfileExpandedPhoto`. Начинается после приёмки P3a.

### 2.14.1a. Уточнения до P3a и P3b (ревью 2.14 v2)

- Уточнения (ревью 2.14 v2): (1) in-flow слот аватара в C перестаёт рисовать, но сохраняет клик, семантику и размер, иначе будет два аватара в покое; (2) в P3a слой имеет размер 112 dp, а не 320 dp; общий `TelegramAvatar` не меняется; (3) стейдж публикует входы (высоты, stage top, toolbar bottom) в холдер, модель считается из холдера, а scroll читается на draw-стороне.
- До P3b: `minHeight` через `Modifier.layout` (без перекомпоновки на каждый кадр); клип снимается непрерывной интерполяцией по `collapse` (без скачка при `collapse ≥ 0.8`); один механизм вместо заморозки `travel` (travel считается от замороженного входа `scrollAtGestureStart`, а не отдельным флагом).
- P1.2 (квадратный слой, `clipTopPx`) можно вести параллельно с P3a.

### 2.14.2. Единый рендерер для P3 (только аватар и фото)

- Рисует один слой: аватар/фото. Текст (имя, статус, бейджи) остаётся по рукопожатию P2b: в потоке в покое, в оверлее при сворачивании. Полный рендерер текста — отдельный шаг после приёмки морфа.
- Слой — **квадрат** со стороной `layerSide = max(photoW, photoH, avatarPx)` (B3). Клип — прямоугольник `avatarRect`, режет слой симметрично. `cover = max(clipW, clipH) / layerSide`, одинаковый по осям. Без искажения.
- `overscale = 1` в P3. Значение 1.2 включается в P4 вместе с параллаксом. `parallaxPx = 0` в P3.
- Заполнитель: слой сам рисует инициалы и цвет акцента, пока файл не загружен (как `TelegramAvatar`). Малый файл — то, что уже есть для аватара; большой запрашивается только при `reveal > 0`, и кроссфейд малый → большой идёт внутри этого же узла.

### 2.14.3. Откуда берётся `reveal`

- `reveal` передаётся как `() -> Float`. Высота стейджа зависит от `reveal` (раскрытие меняет поток), поэтому стейдж читает его в `measure/layout`: перераскладывается место, а не содержимое. Это не рекомпозиция всего экрана.
- Слой фото читает `reveal`, `collapse` и клип только в draw-фазе (`graphicsLayer`/`drawWithContent`).
- Стейдж публикует rect (`avatarRect`, `titleRect`, `statusRect`, `badgesRect`) в холдер. Экран читает их из холдера. Модель вызывается в одном месте: стейдж. Экранный `collapse` берётся из того же результата, а не из второго вызова с другими входами.
- Входы модели передаются полностью: `hasPhoto`, `viewportHeightPx` и `reveal`, а не жёсткие `false` и `0`, как в P2b.
- Условия (`overlay`, кликабельность аватара) — `derivedStateOf { Boolean }`, перерисовка только на границах 0 и 1.

### 2.14.4. Клип и тулбар

- Клип фото ограничен нижним краем тулбара, пока форма шире круга. Модель выдаёт `clipTopPx(collapse)`: при `collapse = 0` клип не ограничен, при `collapse ≥ 0.8` клип снят полностью. Компактный аватар 40 dp внутри тулбара не режется.
- Тест: при `collapse = 1` клип не режет `compactAvatar`; при `collapse = 0` клип не меньше слоя.
- Альтернатива (кроссфейд в компактный аватар тулбара при `collapse → 1`) остаётся запасным вариантом, если клип даст видимый разрыв; решение на устройстве.

### 2.14.5. Переход чат ↔ профиль (B4, дыра 4)

- Слой множит alpha на `headerVisibility()` и скрыт при `flightActive()`. Во время push, pop и жеста Back на экране один аватар: либо полёт, либо слой.
- Полёт стартует и приземляется на `avatarRect` модели в **круглом** состоянии. Отчёты публикуются из модели (`snapshotFlow` по производным значениям), а не из `onGloballyPositioned`: тот не срабатывает на слоевые трансформации.
- Тест: отчёты равны rect модели при `reveal = 0` и `collapse = 0`.

### 2.14.6. Таблица тапа по аватару (B1)

| Состояние | Тап |
|---|---|
| `reveal = 0`, `scroll = 0`, фото есть и `revealEnabled` | раскрыть |
| `reveal = 1` | галерея |
| `scroll > 0` | галерея |
| фото нет или `revealEnabled = false` | галерея |
| автомат в Opening или Closing | игнорировать |

Сворачивание не тапом: Back, стрелка тулбара, прокрутка и (для TalkBack) пользовательское действие «свернуть фото».

### 2.14.7. Конечный автомат раскрытия (дыра 2)

- Состояния: Closed → Opening → Open → Closing. Прерывание анимации — retarget от текущего значения, без скачка.
- Эффективный `reveal` = `revealEnabled ? значение : 0`. Сохраняется только булево (`rememberSaveable`, как сейчас). После поворота, когда раскрытие отключено, сохранённое булево игнорируется.
- Поворот или смена ширины при раскрытом фото: `reveal` восстанавливается в целевое значение без анимации; `scroll` клампится.

### 2.14.8. Back и стрелка (дыры 1, 9)

- Системный Back и стрелка тулбара идут через один `leaveProfile()`.
- При `reveal > 0` или `scroll > 0`: сначала анимированный `scrollTo(0)` (если нужно), затем свёртка фото (`reveal → 0`), затем выход. Во время свёртки повторный Back потребляется.
- `travel` **замораживается** на время свёртки, чтобы `collapse` не прыгал при изменении высоты стейджа.
- `PredictiveBackHandler` с прогрессом `reveal = 1 − progress` (рекомендация ревью). Если на P3b это не успевает, `BackHandler(enabled = reveal > 0)` с явной записью ограничения «превью жеста не показывается».
- Галерея композируется позже, её Back приоритетнее: подтвердить на устройстве.

### 2.14.9. Reduced motion (дыра 3)

- Раскрытие и сворачивание без пружины: мгновенно или короткий кроссфейд 150 мс. Выбор `AnimationSpec` — чистая функция, с тестом.
- Параллакс 0 (уже в модели при `reduceMotion`).

### 2.14.10. TalkBack (B5, дыра 5)

- Аватар остаётся кнопкой в стейдже. Его слот переразмеряется по `avatarRect` в `measure` (не фиксированные 112 dp), поэтому тап-цель и границы TalkBack следуют морфу.
- `contentDescription` = `a11y_profile_photo_open` (уже есть). `stateDescription` = `a11y_profile_photo_expanded_state` (уже есть): «открыто / закрыто».
- Пользовательское действие «свернуть фото» — **новая строка** `a11y_profile_photo_collapse` во всех пяти локалях (тест покрытия ресурсов упадёт, если локаль пропущена).
- Имя — `heading()`, статус и бейджи остаются в прозрачном стейдже, иначе TalkBack их потеряет (замечание ревью 2.13).
- Оверлей — `clearAndSetSemantics`.

### 2.14.11. Строки (B5.2)

- `a11y_profile_photo_expand` и `a11y_profile_photo_expanded_state` **не удаляются** в P3a. В P3b строка `expand` удаляется, только если grep по проекту подтверждает отсутствие использований; `expanded_state` остаётся как `stateDescription`.
