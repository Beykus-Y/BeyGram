# Переключение камеры во время записи кружка

Статус: план, код не менялся. Ветка `claude/project-thread-ycfx5a` от DEV (1a80a85). Флаг `VIDEO_NOTE_RECORDING_ENABLED` остаётся выключенным: его включит задача круговой маски.

## Что нужно

- Каждая запись начинается с фронтальной камеры, а если её нет, с основной.
- Переключить на другую камеру (и обратно) можно только во время записи, одной кнопкой на экране записи.
- Без второй камеры кнопка скрыта.
- Зеркало превью только у фронтальной камеры. `PreviewView` отражает её сам, ручной `scaleX` не нужен (см. PR #61).
- Если persistent recording не работает, приложение не падает: запись продолжается с прежней камерой или переключение скрыто, а пользователь видит сообщение.

## Что проверено

- PR #61 (f03b229) разрешает переключение только до записи. Кнопка стоит в композере, рядом с кнопкой записи кружка, и видна только при `VIDEO_NOTE_RECORDING_ENABLED = true`.
- CameraX 1.4.1 (версия проекта) содержит `PendingRecording.asPersistentRecording()`. Метод добавлен в 1.3.0-rc01 и в main помечен `@ExperimentalPersistentRecording`. Исправление «persistent recording may fail to continue recording after switching camera» вышло в 1.4.0-beta02, то есть раньше 1.4.1. Обновлять CameraX не нужно. Источник: https://developer.android.com/jetpack/androidx/releases/camera
- По KDoc `PendingRecording.kt` (androidx-main) persistent-запись не останавливается при отвязке `VideoCapture` и заканчивается только через `stop()` или `close()`. Пока новая камера не активна, кадров нет, поэтому в файле ожидается короткая пауза. Фактическое поведение не проверено. Если камера не подходит по поверхностям, `bindToLifecycle` бросает исключение.
- KDoc советует связывать один `Recorder` с одним `VideoCapture`. Сейчас `bind()` создаёт новые `VideoCapture` и `Recorder` на каждое нажатие, поэтому для переключения их нужно создавать один раз на запись.

## План

1. `VideoNoteRecorder`: создать `Recorder` и `VideoCapture` один раз на запись. При переключении перепривязывать тот же `VideoCapture`. `Preview` можно пересоздавать.
2. Старт: `prepareRecording(...).asPersistentRecording().withAudioEnabled().start(...)` с `@OptIn(ExperimentalPersistentRecording::class)`. Если старт с persistent падает, повторить без неё и скрыть переключение.
3. Переключение: `unbindAll()`, затем `bindToLifecycle(owner, другой селектор, группа с тем же capture)`.
4. Откат: если перепривязка к новой камере падает, вернуть прежнюю камеру, показать сообщение и продолжить запись.
5. Кнопка: в `VideoNoteRecordingOverlay`. Видна с открытия экрана записи и нажимается после события `Start`. Скрыта, если `canSwitchCamera` ложь. Кнопку в композере (`ChatScreen.kt`, около строки 456) удалить.
6. Строки только через `R.string`. Ключи `recorder_switch_to_back_description` и `recorder_switch_to_front_description` уже есть, нужен ключ для сообщения об ошибке переключения.

## Открыто

- Длительность и видимость паузы кадра при перепривязке не измерены.
- Звук при перепривязке не проверен.
- Всё проверяется только на физическом устройстве после включения флага. Сборка идёт только в CI.
